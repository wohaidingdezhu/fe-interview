# 后续优化顺序

更新：2026-10-12。以本轮学习流程完善为基础，不新增登录、云同步或复杂复习算法。

## 第一优先：把关键交互变成持续回归

现有 Node 测试覆盖数据规则与服务端渲染，浏览器交互主要依靠逐次验收。优先覆盖：随机清单完整推进、跳过后继续未读、总结弹窗在开发/生产模式的打开与关闭、跨题定位、浏览器前进后退、关闭标签页再恢复、备份导入及存储失败。验收需验证实际页面和状态，不能只检查组件输出文本。

## 第二优先：继续完善移动端兼容

单题学习页已区分当前题与来源专题：当前题是页面主标题，专题总题数与整篇阅读时长不再进入专注模式，标签标题和分享链接也精确到题号。剩余工作是补充手机真机和 Safari 验收，重点检查固定底栏、虚拟键盘、弹窗滚动及焦点恢复。

## 第三优先：维护内容质量和发布后的访问体验

按专题抽查题解、配图与来源，优先处理高频内容；现有定时链接检查报告应形成可处理的清单。发布后长期打开的旧标签页可能遇到旧动态模块失效，目前可通过“刷新页面”恢复；可进一步增加明确的版本更新提示，同时保证学习位置保留。

## 暂缓

新增学习统计看板、账号、云端存储、自动复习调度。先用现有流程持续学习，收集真实使用中出现的障碍，再决定是否增加功能。
