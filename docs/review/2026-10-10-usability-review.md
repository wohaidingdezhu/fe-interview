# 筛选与阅读体验验收（2026-10-10）

## 本次变化

- 标签筛选默认折叠；已选标签始终可见，可单独移除；多选仍为交集，筛选状态保存在 URL。
- 维护状态筛选和发布状态标记仅在开发模式显示。生产页面忽略旧链接中的维护条件，后续操作会清理该参数。
- 合并 React、Vue、工程化、网络、性能优化、算法与手写等重复分类；读取元数据和旧分类链接时统一归一化。原“浏览器与网络”内容是 HTTP 缓存，归入“网络”；“浏览器”仍独立保留。文章 ID、题号和正文未改变。
- 窄屏文章目录改为底部可折叠面板；选题后收起并聚焦标题，Escape 收起并返回目录按钮；桌面保留侧边目录。
- 搜索支持方向键选择、回车打开、Escape 关闭；组词中的输入法事件不触发快捷键。
- 稳定 Markdown 标题与代码块组件，避免父组件更新时丢失焦点、复制状态；修正历史导航定位与锚点重复留白；代码块支持键盘聚焦和横向滚动。

## 项目整体评估

### 优点

1. 架构适合个人知识库：React 静态站配合 Markdown，无需后端和数据库，部署和维护成本低。
2. 内容发布边界明确：逐题状态、来源、版本和审核时间可追踪，构建阶段过滤未发布内容，正文、搜索、图片同步控制。
3. 内容工程有基础：校验、示例测试、搜索与导入测试、CI 构建共同减少回归；稳定题号和链接方便引用。
4. 阅读链路较完整：正文与搜索按需加载，支持题号定位、标签交集、分类兼容和失败重试，本次补齐窄屏目录与键盘焦点。

### 不足与后续优先级

| 优先级 | 不足 | 建议 |
| --- | --- | --- |
| 高 | UI 回归主要依赖手工验收，现有测试不能覆盖焦点、浏览器历史和响应式交互 | 将本次关键场景转为端到端回归用例，并增加 Safari / 真机抽查 |
| 高 | `main.tsx` 同时承担路由、搜索、加载与布局，部分 JSX 和 CSS 过于密集 | 分离导航状态和搜索组件，整理样式，在保持现有行为的前提下逐步重构 |
| 中 | 全文索引整体下载且体积随内容线性增长，阅读模块也较大 | 先测量真实访问性能，再考虑索引分片、搜索 Worker 和精简高亮语言 |
| 中 | 代码运行器使用 iframe 隔离，但没有执行超时和网络隔离 | 若扩展为开放练习平台，先补齐运行资源限制；当前仅按教学辅助工具定位 |
| 中 | 技术正确性仍需要人工复核，语法和规则校验不能证明答案正确或持续有效 | 按主题维护复核周期，优先复查版本敏感内容和可执行示例 |
| 低 | 客户端页面对搜索引擎、文章分享摘要支持有限，学习进度也未持久化 | 根据增长目标选择预渲染与文章元信息，或先做本地收藏和学习记录 |

当前最适合定位为可持续维护的个人前端知识库与面试复习站。下一阶段优先提高 UI 回归保障和代码可维护性，再按实际使用量优化加载性能。
