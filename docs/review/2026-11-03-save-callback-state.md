# 已排队定位回调的保存状态修复

日期：2026-11-03

## 定向复现

保存失败前已经创建的定位任务，可能在后续状态变化后才执行。上一版回调使用渲染时的 `error`，旧任务仍持有空错误状态，会在存储恢复后写入并移除重试提示。

新增用例保留此前排队的定位任务，在阅读标记保存失败、恢复写入后再执行。使用旧判断稳定复现提示消失；换成最新状态判断后保留错误、未保存记录和重试入口，手动重试仍不改变原标记时间。

## 修复

- 保存和读取错误同步更新状态引用，所有定位任务读取同一个最新错误值。
- 定位回调保持稳定，避免通过回调重新创建间接管理错误状态。
- 浏览器时钟在页面加载前安装，避免混用应用已经创建的原生计时器。
- CI 在完整回归前先运行关键 WebKit 恢复场景；失败附上测试生成的保存及点击记录。

## 验证

- 旧判断在定向用例中失败，位置为“旧定位任务执行后错误提示应保留”。
- 修复后全部保存恢复场景 16 项通过，包含 Chromium、WebKit、手机 WebKit 和开发模式。
- 修复的生产构建通过，完整远端回归随推送验证。
